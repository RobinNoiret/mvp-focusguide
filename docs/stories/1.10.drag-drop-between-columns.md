# Story 1.10: Drag & Drop Between Columns

**Epic:** 1 - Foundation & Today Page (Standalone Daily Task Management)
**Story Number:** 1.10
**Status:** Draft

---

## Story

**As a** user,
**I want** to drag tasks between Today columns,
**so that** I can easily update task status.

---

## Acceptance Criteria

1. dnd-kit integrated in Today page
2. Columns are droppable zones
3. Task cards are draggable
4. Visual feedback during drag
5. Dropping updates today_status optimistically
6. Background PATCH /v1/tasks/:id with new status
7. Touch device support
8. Keyboard alternative: arrow keys + Enter
9. No-op if dropped in same column
10. "Done" column checks checkbox
11. Rollback on API failure
12. Smooth animations
13. ARIA live regions announce changes

---

### Task 2: Setup DndContext in Today Page (AC: 1, 2)

- [ ] Wrap KanbanBoard with DndContext in `TodayPage`:
  ```typescript
  import { DndContext, DragEndEvent, DragOverlay, DragStartEvent } from '@dnd-kit/core'

  export default function TodayPage() {
    const [activeTask, setActiveTask] = useState<Task | null>(null)

    const handleDragStart = (event: DragStartEvent) => {
      const task = tasks.find(t => t.id === event.active.id)
      setActiveTask(task || null)
    }

    const handleDragEnd = (event: DragEndEvent) => {
      const { active, over } = event
      if (!over) return

      const taskId = active.id as string
      const newStatus = over.id as TodayStatus

      if (newStatus && newStatus !== activeTask?.today_status) {
        // Update task status (AC 5, 6)
        handleStatusChange(taskId, newStatus)
      }

      setActiveTask(null)
    }

    return (
      <DndContext
        onDragStart={handleDragStart}
        onDragEnd={handleDragEnd}
      >
        <KanbanBoard tasks={tasks} />
        <DragOverlay>
          {activeTask && <TaskCard task={activeTask} isDragging />}
        </DragOverlay>
      </DndContext>
    )
  }
  ```

## Dev Notes

### Why dnd-kit Over React DnD

[Source: docs/architecture.md#Tech Stack]

**dnd-kit Advantages:**
- Modern, React 18 compatible
- Better TypeScript support
- Smaller bundle size (~15KB vs ~45KB)
- Built-in accessibility (keyboard, screen reader)
- Touch device support out-of-the-box
- Active maintenance
- Excellent documentation

**React DnD Considerations:**
- Older library (more mature)
- HTML5 backend (doesn't work on mobile)
- Requires touch backend for mobile (more setup)
- Larger bundle size
- Less active development

**Decision:** Use dnd-kit for modern stack, better mobile support, and accessibility.

### dnd-kit Core Concepts

[Source: dnd-kit Documentation]

**DndContext:**
- Top-level provider wrapping draggable/droppable components
- Manages drag state
- Handles sensors (mouse, touch, keyboard)
- Emits events: onDragStart, onDragEnd, onDragOver

**useDraggable:**
- Hook to make element draggable
- Returns: `attributes`, `listeners`, `setNodeRef`, `transform`
- Apply to task cards

**useDroppable:**
- Hook to make element accept drops
- Returns: `setNodeRef`, `isOver`
- Apply to kanban columns

**DragOverlay:**
- Shows copy of dragged element following cursor
- Renders outside normal DOM flow
- Allows styling without affecting original element

**Sensors:**
- Mouse: Desktop drag
- Touch: Mobile/tablet drag
- Keyboard: Accessibility

### Touch vs Mouse Drag Behavior

**Mouse Drag:**
- Immediate drag on mousedown
- Cursor changes to grabbing
- Smooth following of cursor

**Touch Drag:**
- Delay before drag starts (250ms)
- Distinguishes from scroll gesture
- Haptic feedback on start
- Larger touch targets

**Why delay on touch?**
Users expect to scroll kanban horizontally/vertically. Immediate drag would conflict with scroll. Delay allows scroll gesture, long-press triggers drag.

**Testing touch:**
- Use Chrome DevTools device emulation
- Test on real iOS/Android devices
- Verify scroll vs drag works intuitively

### Keyboard Navigation Implementation

[Source: docs/prd.md#AC 8 + WCAG 2.1]

**Why keyboard navigation?**
- Accessibility for users who can't use mouse
- Power users prefer keyboard
- WCAG requirement for interactive elements

**Keyboard flow:**
1. Tab to task card (focus visible)
2. Press Space/Enter to pick up task
3. Arrow keys to move between columns:
   - Left/Right: Navigate columns
   - Up/Down: Navigate tasks within column
4. Press Space/Enter to drop task
5. Press Escape to cancel

**Challenges:**
- Custom coordinate logic for column navigation
- Visual feedback for keyboard users
- Screen reader announcements

**Implementation:**
dnd-kit provides `KeyboardSensor` with custom `coordinateGetter` function. Define logic for how arrow keys translate to position changes.

### ARIA Live Regions Strategy

[Source: WCAG 2.1 + Accessibility Best Practices]

**What are ARIA live regions?**
Screen readers announce dynamic content changes. User hears updates without moving focus.

**Politeness levels:**
- `aria-live="polite"`: Announce when user pauses (use for drag & drop)
- `aria-live="assertive"`: Announce immediately (use for errors)
- `aria-live="off"`: Don't announce

**For drag & drop:**
Use `polite` for status updates:
- "Picked up Task title"
- "Moved Task title to Done"
- "Drop cancelled"

**Implementation:**
```tsx
<div role="status" aria-live="polite" className="sr-only">
  {announceMessage}
</div>
```

**Timing:**
Update message on drag events, clear after 3 seconds to avoid clutter.

### Optimistic Updates for Drag & Drop

[Source: docs/prd.md#NFR2]

**Drag & drop flow:**
1. User drags task to new column
2. **Optimistic:** Task moves immediately (React Query cache update)
3. **Background:** API call PATCH /v1/tasks/:id with new status
4. **Success:** Real data replaces optimistic (usually identical)
5. **Error:** Rollback to original column, show error toast

**Why optimistic for drag & drop?**
- Drag & drop feels sluggish without instant feedback
- User expects immediate response to physical gesture
- Critical for good UX

**Rollback animation:**
If API fails, task smoothly slides back to original column with error indicator.

### No-op Optimization (AC 9)

**Scenario:**
User drags task from "Backlog" column, drops it back in "Backlog".

**Without optimization:**
- Triggers handleDragEnd
- Calls API: PATCH /v1/tasks/:id with status=backlog
- Server updates (no change)
- Wastes bandwidth, server resources

**With optimization (AC 9):**
```typescript
if (task.today_status === newStatus) {
  return // Skip API call
}
```

**Benefits:**
- No unnecessary API calls
- Faster UX (no loading state)
- Reduced server load

**Edge case:**
What if user drags task out of column then back in same drag gesture? dnd-kit handles this - only final drop position matters.

### Drag Handle vs Full Card Dragging

**Option 1: Full card draggable**
- Entire card area triggers drag
- Simpler UX (no need to find handle)
- More intuitive for most users
- **Recommended for MVP**

**Option 2: Drag handle (six dots icon)**
- Small icon on left/right of card
- More precise control
- Prevents accidental drags
- Better for dense UIs with many interactive elements

**Hybrid approach:**
Full card draggable EXCEPT interactive elements (checkbox, edit/delete icons).

**Implementation:**
```typescript
<div className="task-card">
  <input type="checkbox" onClick={(e) => e.stopPropagation()} />
  <div {...listeners} className="flex-1"> {/* Only this area draggable */}
    {task.title}
  </div>
  <button onClick={handleEdit}>Edit</button>
</div>
```

### Animation Performance Best Practices

**GPU-Accelerated Properties:**
- `transform` (translate, scale, rotate) ✓
- `opacity` ✓
- These trigger GPU compositing, smooth 60 FPS

**CPU-Heavy Properties (Avoid):**
- `top`, `left`, `width`, `height` ✗
- `margin`, `padding` ✗
- These trigger layout recalculation, laggy

**dnd-kit uses transforms:**
```typescript
const style = transform ? {
  transform: `translate3d(${transform.x}px, ${transform.y}px, 0)`,
} : undefined
```

`translate3d` forces GPU acceleration (even for 2D movement).

**CSS Transitions:**
```css
.task-card {
  transition: transform 250ms ease-out, opacity 150ms ease;
  will-change: transform; /* Hint to browser for optimization */
}
```

**Avoid will-change on everything:**
Only use on elements that will animate. Overuse consumes memory.

### Touch Activation Constraint Rationale

**Problem:**
On mobile, users scroll kanban by swiping. Immediate drag would conflict - every scroll attempt would trigger drag.

**Solution:**
Add activation constraint:
```typescript
activationConstraint: {
  delay: 250, // Wait 250ms before drag starts
  tolerance: 5, // Allow 5px movement before canceling
}
```

**Behavior:**
- Quick swipe: Scrolls (drag doesn't activate)
- Long press (>250ms): Drag starts
- Movement >5px before 250ms: Cancels drag, allows scroll

**User feels:**
- Natural scrolling (no accidental drags)
- Intentional long-press for drag
- Haptic feedback confirms drag started

### Rollback UX for Failed Drop

**Scenario:**
1. User drags task from "Backlog" to "Done"
2. Network error or 403 Forbidden
3. Task should return to "Backlog"

**Without animation:**
Task suddenly pops back to Backlog. Confusing.

**With animation:**
1. Task slides smoothly back to Backlog (300ms)
2. Brief red flash or shake
3. Error toast: "Impossible de déplacer la tâche"
4. User understands: API failed, task not moved

**Implementation:**
```typescript
onError: (err, variables, context) => {
  // Rollback cache
  queryClient.setQueryData(['today', 'tasks'], context.previousTasks)

  // Animate rollback (dnd-kit handles this automatically)
  // Add red flash via temporary class
  const taskEl = document.querySelector(`[data-task-id="${taskId}"]`)
  taskEl?.classList.add('rollback-error')
  setTimeout(() => taskEl?.classList.remove('rollback-error'), 500)

  // Show error toast
  toast.error('Impossible de déplacer la tâche. Réessayez.')
}
```

```css
.rollback-error {
  animation: shake 300ms, flash-red 500ms;
}

@keyframes shake {
  0%, 100% { transform: translateX(0); }
  25% { transform: translateX(-5px); }
  75% { transform: translateX(5px); }
}

@keyframes flash-red {
  0%, 100% { border-color: transparent; }
  50% { border-color: #EF4444; }
}
```
