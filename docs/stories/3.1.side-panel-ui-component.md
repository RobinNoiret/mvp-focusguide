# Story 3.1: Side Panel UI Component

**Epic:** 3 - Connection Layer (Bridge Projects and Today with Bidirectional Sync)
**Story Number:** 3.1
**Status:** Draft

---

## Story

**As a** user,
**I want** a side panel on the Today page,
**so that** I can access project tasks without leaving my daily view.

---

## Acceptance Criteria

1. Right side panel added to Today layout (300-350px wide)
2. Panel header with project selector dropdown "Projet - [Sélectionner]"
3. Panel body empty initially
4. Styled per mockup: white background, proper spacing
5. Responsive: collapses to modal on tablet/mobile
6. Subtle border separating from kanban
7. Independent scroll
8. Placeholder: "Sélectionnez un projet..."
9. Dropdown with chartreuse focus
10. Component allows task list addition

### Task 3: Create Responsive Wrapper Component (AC: 5)

- [ ] Create `apps/web/components/today/ResponsiveSidePanel.tsx`:
  ```typescript
  'use client'

  import { ReactNode, useState } from 'react'
  import { SidePanel } from './SidePanel'
  import { SidePanelModal } from './SidePanelModal'
  import { useMediaQuery } from '@/hooks/useMediaQuery'

  interface ResponsiveSidePanelProps {
    selectedProjectName?: string
    onProjectSelect: () => void
    children?: ReactNode
  }

  export function ResponsiveSidePanel({
    selectedProjectName,
    onProjectSelect,
    children,
  }: ResponsiveSidePanelProps) {
    const [isModalOpen, setIsModalOpen] = useState(false)
    const isDesktop = useMediaQuery('(min-width: 768px)')

    // AC 5: Desktop shows panel, mobile shows modal
    if (isDesktop) {
      return (
        <SidePanel
          selectedProjectName={selectedProjectName}
          onProjectSelect={onProjectSelect}
        >
          {children}
        </SidePanel>
      )
    }

    return (
      <SidePanelModal
        selectedProjectName={selectedProjectName}
        onProjectSelect={onProjectSelect}
        isOpen={isModalOpen}
        onOpenChange={setIsModalOpen}
      >
        {children}
      </SidePanelModal>
    )
  }
  ```
- [ ] AC 5: Media query to switch between panel and modal
- [ ] Desktop (≥768px): Side panel
- [ ] Mobile (<768px): Modal with FAB trigger

### Task 4: Create useMediaQuery Hook

- [ ] Create `apps/web/hooks/useMediaQuery.ts`:
  ```typescript
  import { useState, useEffect } from 'react'

  export function useMediaQuery(query: string): boolean {
    const [matches, setMatches] = useState(false)

    useEffect(() => {
      const mediaQuery = window.matchMedia(query)
      setMatches(mediaQuery.matches)

      const handler = (event: MediaQueryListEvent) => {
        setMatches(event.matches)
      }

      // Modern browsers
      if (mediaQuery.addEventListener) {
        mediaQuery.addEventListener('change', handler)
        return () => mediaQuery.removeEventListener('change', handler)
      } else {
        // Legacy browsers
        mediaQuery.addListener(handler)
        return () => mediaQuery.removeListener(handler)
      }
    }, [query])

    return matches
  }
  ```
- [ ] Detect screen size changes
- [ ] Return boolean for media query match
- [ ] Handle both modern and legacy browsers

## Dev Notes

### Panel Width Rationale

**Why 320px (80 in Tailwind)?**
- Enough to show task cards comfortably
- Not too wide (doesn't steal space from kanban)
- Matches mockup (300-350px range)
- `w-80` in Tailwind = 20rem = 320px

**Alternative widths considered:**
- `w-72` (288px): Too narrow for task cards
- `w-96` (384px): Too wide, kanban feels cramped

320px is the sweet spot.

### Independent Scroll Behavior

**Why separate scroll?**
```
┌─────────────────┬──────────┐
│                 │ Header   │
│                 ├──────────┤
│   Kanban        │ ↕ Tasks  │
│   (scrolls)     │ (scrolls)│
│                 │          │
└─────────────────┴──────────┘
```

User can:
- Scroll kanban vertically (many tasks)
- Scroll panel independently (long project task list)

**Implementation:**
```typescript
<div className="flex h-full">
  <div className="flex-1 overflow-auto">Kanban</div>
  <aside className="w-80">
    <div className="flex flex-col h-full">
      <div>Header (fixed)</div>
      <div className="flex-1 overflow-y-auto">Body (scrolls)</div>
    </div>
  </aside>
</div>
```

### Responsive Strategy

**Breakpoints:**
- Desktop (≥768px): Side panel visible
- Mobile (<768px): FAB + modal

**Why 768px?**
- Standard tablet breakpoint
- Below 768px, kanban + panel = too cramped
- Modal provides better UX on small screens

**Tailwind breakpoint:**
```typescript
const isDesktop = useMediaQuery('(min-width: 768px)')
// md: breakpoint in Tailwind
```

### Border Separation (AC 6)

**Subtle border:**
```css
border-left: 1px solid #e5e7eb; /* gray-200 */
```

**Why subtle?**
- Clear visual separation
- Not distracting
- Matches overall minimalist design

**Alternative: Shadow**
```css
box-shadow: -2px 0 4px rgba(0,0,0,0.05);
```

Tried, too heavy. Border is cleaner.

### Placeholder Text (AC 8)

**"Sélectionnez un projet..."**

**Alternatives considered:**
- "Aucun projet sélectionné" → Too formal
- "Choisissez un projet pour voir ses tâches" → Too long
- "Sélectionnez un projet..." → Just right

**Styling:**
```css
color: #6b7280; /* gray-500 */
text-align: center;
font-size: 0.875rem; /* 14px */
```

Soft, unobtrusive, guides user.

### Chartreuse Focus Styling (AC 9)

**Focus ring:**
```css
focus:border-[#D9FC00]
focus:ring-2
focus:ring-[#D9FC00]
focus:ring-offset-2
```

**Why chartreuse?**
- Brand color
- High visibility
- Indicates interactivity

**Accessibility:**
- Focus visible for keyboard users
- 2px ring exceeds WCAG requirements
- Offset prevents overlap with border

### Component Composition (AC 10)

**Why children prop?**
```typescript
<SidePanel>
  {/* Story 3.3: Project task list */}
</SidePanel>
```

**Flexibility:**
- Story 3.1: Empty placeholder
- Story 3.3: Task list
- Story 3.4: Draggable task cards

Component is reusable, content varies.

### Mobile Modal UX (AC 5)

**Sheet vs Dialog:**
- Sheet: Slides from side
- Dialog: Centers on screen

**Why Sheet?**
- Feels like panel extension
- Slide-in animation matches side panel
- Swipe-to-close gesture natural on mobile

**shadcn/ui Sheet:**
- Accessible (ARIA, keyboard)
- Touch-friendly
- Smooth animations

### FAB (Floating Action Button)

**Why FAB on mobile?**
- Always accessible (doesn't scroll away)
- Clear affordance ("Projets" label + icon)
- Standard mobile pattern

**Position:**
```css
position: fixed;
bottom: 1rem;
right: 1rem;
z-index: 50;
```

**Icon:**
FolderKanban - represents projects.

### Header Fixed, Body Scrolls

**Layout:**
```
┌──────────────┐
│ Header       │ ← Fixed
├──────────────┤
│ Body         │ ↕ Scrolls
│              │
│              │
└──────────────┘
```

**CSS:**
```typescript
<div className="flex flex-col h-full">
  <div className="border-b p-4">Header</div>
  <div className="flex-1 overflow-y-auto p-4">Body</div>
</div>
```

`flex-1` makes body take remaining height.
`overflow-y-auto` enables scroll.

### Accessibility Considerations

**ARIA attributes:**
- `role="complementary"` - Side panel is supplementary content
- `aria-label` - Describes panel purpose
- `aria-haspopup="listbox"` - Indicates dropdown
- `aria-expanded` - Dropdown state (Story 3.2)

**Keyboard navigation:**
1. Tab to project selector button
2. Enter/Space to open dropdown
3. Arrow keys to navigate projects (Story 3.2)
4. Enter to select
5. Escape to close

**Screen reader:**
"Panneau de sélection de projet, complémentaire. Bouton: Projet - Sélectionner. Activez pour ouvrir la liste des projets."

### Performance: useMediaQuery Hook

**Why custom hook?**
- React to screen size changes
- SSR-safe (no window.matchMedia on server)
- Reusable across components

**Implementation:**
```typescript
useEffect(() => {
  const mediaQuery = window.matchMedia(query)
  // Listen for changes
}, [query])
```

**Alternative: CSS-only**
```css
@media (min-width: 768px) {
  .side-panel { display: block; }
  .fab-button { display: none; }
}
```

But we need JS for Sheet open/close state.

### Z-index Management

**Layers:**
- Kanban: z-0 (default)
- Side panel: z-0 (same layer)
- FAB: z-50 (above content)
- Sheet overlay: z-50 (shadcn/ui default)

**No conflicts:**
FAB and Sheet only on mobile (panel hidden).

### Empty State vs Loading State

**Story 3.1:**
Empty state: "Sélectionnez un projet..."

**Story 3.3:**
Loading state: Skeleton cards while fetching tasks

**Different states:**
- Empty: No project selected (intentional)
- Loading: Project selected, tasks fetching (temporary)

Design both in respective stories.

### Future Enhancement: Resize Panel

**Drag to resize:**
```
┌─────────────┬─┬──────┐
│   Kanban    │║│Panel │
│             │║│      │
└─────────────┴─┴──────┘
              ↕ Drag handle
```

**Not in MVP:**
Fixed 320px is simpler.

**If needed later:**
Use `react-resizable-panels` library.

### Mobile Gesture: Swipe to Close

**Sheet component:**
Built-in swipe gesture (shadcn/ui).

**How it works:**
1. User swipes right (towards edge)
2. Sheet slides out
3. Backdrop fades
4. `onOpenChange(false)` called

**Accessibility:**
Also closable via:
- Backdrop click
- X button
- Escape key

### Styling Consistency

**Colors:**
- Background: White (#FFFFFF) - AC 4
- Border: Gray-200 (#e5e7eb) - AC 6
- Text: Dark (#262626)
- Focus: Chartreuse (#D9FC00) - AC 9
- Placeholder: Gray-500 (#6b7280) - AC 8

**Spacing:**
- Padding: 1rem (16px) - AC 4
- Header/body separation: border-b

**Typography:**
- Font: Inter (body text)
- Size: 14px (text-sm)
- Weight: Medium (font-medium) for button

Matches design system from PRD.

### Transition Animations

**Sheet open/close:**
shadcn/ui provides smooth slide-in/out.

**Desktop panel:**
No animation (always visible).

**Future: Slide-in on first render?**

```css
  to { transform: translateX(0); }

```

But instant appearance is cleaner.
