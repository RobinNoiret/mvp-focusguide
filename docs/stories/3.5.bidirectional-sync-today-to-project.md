# Story 3.5: Bidirectional Sync (Today → Project)

**Epic:** 3 - Connection Layer (Bridge Projects and Today with Bidirectional Sync)
**Story Number:** 3.5
**Status:** Draft

---

## Story

**As a** user,
**I want** Today status changes to update Project kanban,
**so that** I don't manually sync between views.

---

## Acceptance Criteria

1. Task with project_id moved to Done in Today → project_status: done
2. TaskSyncService.applyBidirectionalSync() method in backend
3. Sync logic: today_status=done → project_status=done (if project_id exists)
4. PATCH /v1/tasks/:id calls TaskSyncService
5. Frontend invalidates both caches
6. Task marked done in Today shows done in Project
7. Checkbox in Today triggers sync
8. Panel card updates to "Done" badge
9. Unit test: project task → Today → mark done → verify project_status
10. Integration test: verify Project detail shows done

---

### Task 1: Create TaskSyncService in Backend (AC: 2, 3)

- [ ] Create `apps/api/app/Services/TaskSyncService.ts`:
  ```typescript
  import Task from 'App/Models/Task'
  import type { TodayStatus, ProjectStatus } from '@focus-guide/shared'

  export class TaskSyncService {
    /**
     * AC 2, 3: Apply bidirectional sync logic
     * When task is marked done in Today, mark done in Project
     */
    public static async applyBidirectionalSync(task: Task): Promise<void> {
      // AC 3: Sync today_status=done → project_status=done
      if (task.today_status === 'done' && task.project_id) {
        task.project_status = 'done'
        await task.save()
      }

      // Story 3.6 will add: project_status=done → today_status=done
    }

    /**
     * Map TodayStatus to ProjectStatus (if needed)
     * For now, only "done" syncs. Future could sync all statuses.
     */
    private static mapTodayToProjectStatus(
      todayStatus: TodayStatus
    ): ProjectStatus | null {
      if (todayStatus === 'done') {
        return 'done'
      }
      // Other statuses don't sync (yet)
      return null
    }
  }
  ```
- [ ] AC 2: Service class for sync logic
- [ ] AC 3: today_status=done → project_status=done

- [ ] Centralizes sync rules

### Task 2: Update TasksController to Call TaskSyncService (AC: 4)

- [ ] Update `apps/api/app/Controllers/Http/TasksController.ts`:
  ```typescript
  import type { HttpContextContract } from '@ioc:Adonis/Core/HttpContext'
  import Task from 'App/Models/Task'
  import { TaskSyncService } from 'App/Services/TaskSyncService'

  export default class TasksController {
    public async update({ params, request, auth, response }: HttpContextContract) {
      const user = auth.user!
      const taskId = params.id

      const task = await Task.query()
        .where('id', taskId)
        .where('user_id', user.id)
        .whereNull('deleted_at')
        .firstOrFail()

      const payload = await request.validate(UpdateTaskValidator)

      // Update task fields
      task.merge(payload)

      // AC 4: Apply bidirectional sync
      if (payload.today_status || payload.project_status) {
        await TaskSyncService.applyBidirectionalSync(task)
      } else {
        await task.save()
      }

      return response.ok(task)
    }
  }
  ```
- [ ] AC 4: Call TaskSyncService on every task update
- [ ] Sync runs before returning response
- [ ] Returns updated task with synced statuses

## Dev Notes

### Sync Direction: Today → Project (AC 1, 3)

**Logic:**
```
today_status=done + project_id exists → project_status=done
```

**Why only "done"?**
- Most critical status (task completion)
- Other statuses are workflow-specific
- Keeps sync simple for MVP

**Future enhancement:**
```typescript
today_status=in_progress → project_status=in_progress
```

### TaskSyncService Responsibility (AC 2)

**Why separate service?**
- Centralize sync logic
- Reusable across controllers
- Easier to test
- Clear separation of concerns

**Alternative:**
Put logic directly in TasksController.

**But:**
- Violates Single Responsibility
- Harder to test
- Less flexible for future changes

### Sync Timing (AC 4)

**When does sync happen?**
```
User marks done → PATCH /v1/tasks/:id → TaskSyncService → Save
```

**Synchronous:**
Sync happens in same request.

**Benefit:**
Response includes both statuses updated.

**Drawback:**
Slightly slower response (negligible).

### Frontend Cache Invalidation (AC 5)

**Why invalidate both?**
```typescript
queryClient.invalidateQueries(['today'])
queryClient.invalidateQueries(['projects', projectId])
```

**Scenario:**
1. User marks task done in Today
2. Backend syncs project_status
3. Frontend invalidates caches
4. Both Today and Project refetch
5. Both show updated status

**Without invalidation:**
Project cache stale, shows old status.

### Checkbox Behavior (AC 7)

**Toggle:**
```typescript
done → todo (unchecked)
todo → done (checked)
```

**Why toggle to "todo"?**
- Simple logic
- User can drag to correct column if needed
- MVP approach

**Alternative:**
Store previous status, toggle back.

**More complex, minimal benefit.**

### Panel Card Update (AC 8)

**Badge changes:**
```
Before sync: "À faire"
After sync:  "Terminé"
```

**How?**
1. Cache invalidated
2. Refetch project tasks
3. Task now has project_status=done
4. Badge updates automatically

**React Query magic.**

### Edge Case: No project_id

**Scenario:**
Standalone task marked done in Today.

**Behavior:**
```typescript
if (task.project_id) {
  // Sync
}
// Else: No sync, no error
```

**Result:**
Standalone tasks work normally.

### Edge Case: Multiple Syncs

**Scenario:**
1. Mark done in Today → sync to Project
2. Uncheck in Today (mark todo) → ???

**Current behavior:**
No reverse sync (done → todo).

**Future enhancement:**
```typescript
if (task.today_status !== 'done' && task.project_status === 'done') {
  // Reverse sync?
}
```

**For MVP:**
One-way sync (done only).

### Testing Strategy

**Unit tests:**
- TaskSyncService logic
- Sync only if project_id
- Sync only if done

**Integration tests:**
- E2E: Today → Project
- Verify both views updated

**Visual tests:**
- Badge changes in panel
- Checkmark in Today

### Performance: Sync Cost

**Additional DB write:**
```sql
UPDATE tasks SET project_status = 'done' WHERE id = ?
```

**Concern:**
Slower response?

**Measurement:**
- Write: ~5ms
- Negligible impact

**Trade-off:**
Data consistency > 5ms latency.

### Future: Configurable Sync

**User preference:**
"Sync Today and Projects"
- On (default)
- Off

**Why?**
Some users may want manual control.

**Not in MVP:**
Assume sync is always on.

### Sync Indicator in UI

**Current:**
No visual feedback that sync happened.

**Enhancement:**
```
Toast: "Tâche marquée comme terminée dans Projet Test"
```

**Benefit:**
User knows sync occurred.

**Drawback:**
Extra noise (toast fatigue).

**Decision:**
Optional for MVP.
