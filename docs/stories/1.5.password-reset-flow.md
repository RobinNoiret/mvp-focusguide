# Story 1.5: Password Reset Flow

**Epic:** 1 - Foundation & Today Page (Standalone Daily Task Management)
**Story Number:** 1.5
**Status:** Draft

---

## Story

**As a** user who forgot their password,
**I want** to reset my password via email,
**so that** I can regain access to my account.

---

## Acceptance Criteria

1. Forgot password page (/forgot-password) with email input
2. POST /v1/auth/forgot-password generates reset token (1h expiry), sends email
3. Generic success message (prevent email enumeration)
4. Rate limiting: 3 requests/hour per email
5. Reset password page (/reset-password) with new password, confirm password
6. POST /v1/auth/reset-password validates token, hashes password, invalidates sessions
7. Password validation matches registration
8. Success redirects to login
9. Expired/invalid tokens show error
10. Unit tests for reset flow

  - Accept `{ email: string }`
  - Validate email format with VineJS
  - Find user by email (fail silently if not found - security)

  - Set expiry to 1 hour from now
  - Delete any existing unexpired tokens for this user
  - Save token to database
  - Queue email sending (async)
  - Always return generic success: `{ message: "If email exists, reset link sent" }`
- [ ] Implement rate limiting for forgot-password endpoint:
  - Use `@adonisjs/limiter` middleware
  - Limit: 3 requests per hour per email address
  - Return 429 Too Many Requests if exceeded
  - Store rate limit in Redis with key: `reset_attempt:{email}`
- [ ] Create email template for password reset:

### Task 2: Backend - Password Reset Validation & Update (AC: 6, 7, 9)

- [ ] Implement POST `/v1/auth/reset-password` endpoint:
  - Accept `{ token: string, password: string, password_confirmation: string }`
  - Validate inputs with VineJS:
    - `token` required, string
    - `password` required, min 8 chars, matches registration rules
    - `password_confirmation` required, matches password
  - Find token in database by token string
  - If token not found: return 400 Bad Request `{ error: "Invalid or expired reset token" }`
  - Check if token is expired using `isExpired()`:
    - If expired: delete token, return 400 `{ error: "Reset token has expired" }`
  - Get associated user via relationship
  - Hash new password with bcrypt (cost 10+)
  - Update user password in database
  - Mark token as used (soft delete or add `used_at` timestamp)
  - Invalidate all existing user sessions (logout from all devices):
    - Delete all active sessions for user_id from Redis
    - Invalidate all refresh tokens for user
  - Return success: `{ message: "Password reset successful" }`
- [ ] Add password validation rules matching registration (Story 1.3):
  - Minimum 8 characters
  - At least one uppercase letter
  - At least one lowercase letter
  - At least one number
  - At least one special character (optional but recommended)
- [ ] Add unit tests for token validation:

## Dev Notes

### Password Reset Security Best Practices

[Source: docs/architecture.md#Security Architecture]

Password reset flows are a common attack vector. This implementation follows OWASP best practices:

**Email Enumeration Prevention (AC 3):**
- Always return the same success message whether email exists or not
- Use consistent response times (don't leak information via timing)
- This prevents attackers from discovering valid user emails

**Rate Limiting (AC 4):**
- Prevents brute force attacks on reset tokens
- Limits abuse of email sending
- Implemented at multiple levels: per-email and per-IP

**Token Security:**
- Tokens must be cryptographically secure: `crypto.randomBytes(32)`
- Tokens are single-use (marked as used after successful reset)
- Short expiry window (1 hour) reduces attack window
- Consider hashing tokens in database for defense in depth

**Session Invalidation:**
- All active sessions invalidated on password reset
- Forces re-authentication with new password
- Protects user if their account was compromised

### Email Service Configuration

[Source: docs/prd.md#Technical Assumptions]

**Development Environment:**
Use Mailtrap (https://mailtrap.io) or Ethereal (https://ethereal.email) for email testing. These services capture emails without sending them to real addresses.

**Production Environment:**
Choose a transactional email service:
- **SendGrid** - Generous free tier, good deliverability
- **Mailgun** - Developer-friendly API
- **AWS SES** - Cost-effective for high volume

**Email Template Requirements:**
- Must include Focus Guide branding (chartreuse accent)
- Responsive design (mobile-friendly)
- Clear call-to-action button
- Security disclaimer
- Plain text fallback for accessibility

### Rate Limiting Implementation

[Source: docs/architecture.md#Security Architecture + docs/prd.md#NFR10]

**Rate Limit Strategy:**
```
Auth endpoints: 5 req/min per IP (covers forgot-password)
Specific to forgot-password: 3 req/hour per email
```

**Implementation with @adonisjs/limiter:**
```typescript
// In routes file
Route.post('/auth/forgot-password', [AuthController, 'forgotPassword'])
  .use(throttle({
    duration: '1 hour',
    requests: 3,
    key: (ctx) => ctx.request.input('email')
  }))
```

**Redis Storage:**
Rate limit counters stored in Redis with automatic TTL expiry.

### Token Expiry & Cleanup

**Token Expiry:**
- Set to 1 hour from generation (AC 2)
- Validated on every reset attempt (AC 9)
- Expired tokens cannot be used

**Cleanup Strategy:**
Create a scheduled job to delete expired tokens:
```typescript
// Cron job: Run daily at 2 AM
Scheduler.call(async () => {
  await PasswordResetToken.query()
    .where('expires_at', '<', DateTime.now())
    .delete()
})
```

This prevents database bloat from unused/expired tokens.

### Password Validation Consistency

[Source: docs/prd.md#Story 1.3 + Story 1.5 AC 7]

**CRITICAL:** Password validation rules MUST match registration (Story 1.3).

**Validation Rules:**
- Minimum 8 characters
- At least one uppercase letter (A-Z)
- At least one lowercase letter (a-z)
- At least one number (0-9)
- At least one special character (recommended): `!@#$%^&*`

**Reuse Validation Logic:**
Create shared validation schema in `packages/shared` or backend validators:
```typescript
// packages/shared/src/validators/password.ts
export const passwordSchema = {
  minLength: 8,
  requireUppercase: true,
  requireLowercase: true,
  requireNumber: true,
  requireSpecial: true,
}
```

This ensures consistency across registration, password reset, and future password change features.

### Session Invalidation Strategy

[Source: docs/prd.md#Story 1.5 AC 6]

When a user resets their password, all existing sessions must be invalidated to prevent unauthorized access.

**Implementation Steps:**
1. Delete all active sessions for user from Redis:
   ```typescript
   await redis.del(`session:user:${userId}:*`)
   ```
2. Invalidate all refresh tokens in database:
   ```typescript
   await RefreshToken.query()
     .where('user_id', userId)
     .update({ revoked_at: DateTime.now() })
   ```
3. User must log in again with new password

**Rationale:**
If the password reset was triggered because the account was compromised, this ensures the attacker is immediately logged out from all devices.

### Frontend UX Considerations

**Success Message Timing:**
After successful password reset, show success message for 2-3 seconds before auto-redirecting to login. This gives user time to read the message but doesn't require manual action.

**Alternative:** Provide both auto-redirect and manual "Go to login" button for user control.

**Error Handling:**
- Expired token: Provide link to request new reset email
- Invalid token: Suggest checking email for correct link
- Network error: Allow retry without re-entering data

For manual testing of expired tokens:

**Option 1:** Manually update database:
```sql
UPDATE password_reset_tokens
SET expires_at = NOW() - INTERVAL '1 hour'
WHERE token = 'your-test-token';
```

**Option 2:** Create test endpoint (development only):
```typescript
// Remove in production
Route.post('/test/expire-token/:token', async ({ params }) => {

    .where('token', params.token)
    .update({ expires_at: DateTime.now().minus({ hours: 1 }) })
})
```
