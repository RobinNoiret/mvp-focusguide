# Story 2.7: Project Deletion with Cascade

**Epic:** 2 - Projects Management (Strategic Planning Layer)
**Story Number:** 2.7
**Status:** Draft

---

## Story

**As a** user,
**I want** to delete projects I no longer need,
**so that** my projects list stays clean.

---

## Acceptance Criteria

1. Three-dot menu has "Supprimer" option
2. Confirmation modal: "Supprimer ce projet? Toutes les tâches..."
3. Confirm calls DELETE /v1/projects/:id
4. Backend soft deletes project and cascade soft deletes tasks
5. Tasks in Today removed if project deleted
6. Card disappears optimistically
7. If on detail page, navigate to /projects with toast
8. Rollback on failure
9. React Query invalidates projects and today caches
10. Unit test: create project → tasks → delete → verify cascade
11. Integration test: verify Today removes cascaded tasks

### Task 3: Create useDeleteProject Hook (AC: 3, 4, 5, 6, 7, 8, 9)

- [ ] Create `apps/web/hooks/useDeleteProject.ts`:
  ```typescript
  import { useMutation, useQueryClient } from '@tanstack/react-query'
  import { useRouter } from 'next/navigation'
  import { projectService } from '@/services/projectService'
  import type { ProjectWithStats } from '@focus-guide/shared'
  import { toast } from '@/hooks/use-toast'

  export function useDeleteProject() {
    const queryClient = useQueryClient()
    const router = useRouter()

    return useMutation({
      mutationFn: (projectId: string) => projectService.deleteProject(projectId),

      // AC 6, 8: Optimistic delete
      onMutate: async (projectId) => {
        // Cancel outgoing queries
        await queryClient.cancelQueries({ queryKey: ['projects'] })
        await queryClient.cancelQueries({ queryKey: ['projects', projectId] })
        await queryClient.cancelQueries({ queryKey: ['today'] })

        // Snapshot previous values
        const previousProjects = queryClient.getQueryData<ProjectWithStats[]>(['projects'])
        const previousProject = queryClient.getQueryData<ProjectWithStats>(['projects', projectId])
        const previousTodayTasks = queryClient.getQueryData(['today'])

        // AC 6: Optimistically remove project from grid
        queryClient.setQueryData<ProjectWithStats[]>(['projects'], (old) => {
          if (!old) return old
          return old.filter((project) => project.id !== projectId)
        })

        // AC 5: Optimistically remove tasks from Today (cascade)
        queryClient.setQueryData(['today'], (old: any) => {
          if (!old) return old
          // Remove tasks that belong to deleted project
          return {
            ...old,
            tasks: old.tasks?.filter((task: any) => task.project_id !== projectId),
          }
        })

        return { previousProjects, previousProject, previousTodayTasks }
      },

      // AC 8: Rollback on error
      onError: (err, projectId, context) => {
        // Restore previous state
        if (context?.previousProjects) {
          queryClient.setQueryData(['projects'], context.previousProjects)
        }
        if (context?.previousProject) {
          queryClient.setQueryData(['projects', projectId], context.previousProject)
        }
        if (context?.previousTodayTasks) {
          queryClient.setQueryData(['today'], context.previousTodayTasks)
        }

        toast({
          title: 'Erreur',
          description: 'Impossible de supprimer le projet. Veuillez réessayer.',
          variant: 'destructive',
        })
      },

      // AC 7, 9: Navigate and invalidate caches
      onSuccess: (_, projectId, context) => {
        // AC 9: Invalidate both projects and today caches
        queryClient.invalidateQueries({ queryKey: ['projects'] })
        queryClient.invalidateQueries({ queryKey: ['today'] })

        // AC 7: If on detail page, navigate to projects grid
        if (window.location.pathname.includes(`/projets/${projectId}`)) {
          router.push('/projets')
        }

        toast({
          title: 'Succès',
          description: 'Projet supprimé avec succès',
        })
      },
    })
  }
  ```

- [ ] Card disappears optimistically from grid (AC 6)
- [ ] Navigate to /projets if on detail page (AC 7)

### Task 4: Update Backend DELETE /v1/projects/:id Endpoint (AC: 4)

- [ ] Update `apps/api/app/Controllers/Http/ProjectsController.ts`:
  ```typescript
  import type { HttpContextContract } from '@ioc:Adonis/Core/HttpContext'
  import Project from 'App/Models/Project'
  import Task from 'App/Models/Task'
  import Database from '@ioc:Adonis/Lucid/Database'

  export default class ProjectsController {
    // ... other methods ...

    /**
     * AC 3, 4: Delete project with cascade soft delete to tasks
     */
    public async destroy({ params, auth, response }: HttpContextContract) {
      const user = auth.user!
      const projectId = params.id

      // Start transaction for atomic cascade delete
      const trx = await Database.transaction()

      try {
        // Fetch project with ownership check
        const project = await Project.query({ client: trx })
          .where('id', projectId)
          .where('user_id', user.id)
          .whereNull('deleted_at')
          .firstOrFail()

        // AC 4: Cascade soft delete all tasks in this project
        await Task.query({ client: trx })
          .where('project_id', projectId)
          .whereNull('deleted_at')
          .update({ deleted_at: new Date() })

        // Soft delete the project
        project.deleted_at = new Date()
        await project.save()

        await trx.commit()

        return response.noContent()
      } catch (error) {
        await trx.rollback()

        if (error.code === 'E_ROW_NOT_FOUND') {
          return response.notFound({ message: 'Project not found' })
        }

        throw error
      }
    }
  }
  ```
- [ ] Soft delete project (set deleted_at)
- [ ] Cascade soft delete all tasks (AC 4)
- [ ] Transaction ensures atomicity
- [ ] Ownership validation (user can only delete own projects)
- [ ] 404 if project not found or already deleted

    it('deletes project and removes from cache optimistically', async () => {

        expect(projects).toHaveLength(1)

    it('removes project tasks from Today cache on delete', async () => {
      const projectId = 'project-123'
      const mockTodayTasks = {
        tasks: [
          { id: 'task-1', project_id: projectId, title: 'Project Task' },
          { id: 'task-2', project_id: null, title: 'Standalone Task' },
          { id: 'task-3', project_id: 'project-456', title: 'Other Project Task' },
        ],
      }

      vi.mocked(projectService.deleteProject).mockResolvedValue()

      const { result } = renderHook(() => useDeleteProject(), { wrapper })

      queryClient.setQueryData(['today'], mockTodayTasks)

      result.current.mutate(projectId)

      // AC 5: Tasks from deleted project removed from Today
      await waitFor(() => {
        const todayData = queryClient.getQueryData<any>(['today'])
        expect(todayData.tasks).toHaveLength(2)
        expect(todayData.tasks.find((t: any) => t.id === 'task-1')).toBeUndefined()
      })
    })

    it('rolls back on deletion failure', async () => {
      const projectId = 'project-123'
      const initialProjects: ProjectWithStats[] = [
        { id: projectId, title: 'Test Project' } as ProjectWithStats,
      ]

      vi.mocked(projectService.deleteProject).mockRejectedValue(new Error('API Error'))

      const { result } = renderHook(() => useDeleteProject(), { wrapper })

      queryClient.setQueryData(['projects'], initialProjects)

      result.current.mutate(projectId)

      // Wait for error
      await waitFor(() => {
        expect(result.current.isError).toBe(true)
      })

      // AC 8: Check rollback - project still in cache
      const projects = queryClient.getQueryData<ProjectWithStats[]>(['projects'])
      expect(projects).toHaveLength(1)
      expect(projects?.[0].id).toBe(projectId)
    })
  })

## Dev Notes

### Cascade Delete Strategy

**Why soft delete?**
- Preserves data integrity
- Allows potential future "restore" feature
- Audit trail (when was project deleted)
- Simpler than hard delete (no foreign key constraints)

**Database approach:**
```sql
-- Soft delete project
UPDATE projects SET deleted_at = NOW() WHERE id = ?

-- Cascade soft delete tasks
UPDATE tasks SET deleted_at = NOW() WHERE project_id = ?
```

**Transaction safety:**
Both operations must succeed or both fail. Use database transaction.

### Today Cache Cascade Behavior

**Challenge:**
When project is deleted, tasks in Today must be removed immediately.

**Frontend approach:**
Optimistically remove tasks from Today cache where `project_id === deletedProjectId`.

**Backend approach:**
Soft delete marks tasks as deleted. Next Today API call excludes `deleted_at IS NOT NULL`.

**Sync:**
1. Optimistic: Remove immediately
2. Background: DELETE API call
3. On success: Invalidate Today cache
4. Refetch: Server returns tasks without deleted ones

### Optimistic Update Complexity

**Three caches affected:**
1. `['projects']` - Grid view
2. `['projects', projectId]` - Detail view
3. `['today']` - Today page

**All must be updated optimistically:**
```typescript
// Remove from projects grid
queryClient.setQueryData(['projects'], (old) =>
  old.filter((p) => p.id !== projectId)
)

// Remove project detail
queryClient.removeQueries(['projects', projectId])

// Remove tasks from Today
queryClient.setQueryData(['today'], (old) => ({
  ...old,
  tasks: old.tasks.filter((t) => t.project_id !== projectId),
}))
```

**Rollback:**
If API fails, restore all three caches from snapshots.

### Confirmation Dialog UX

**Why emphasize task count?**
Users may not realize deleting a project deletes all tasks.

**Warning text:**
"Toutes les 24 tâches de ce projet seront également supprimées."

**Psychology:**
Red color + task count + "irréversible" → user thinks twice.

**Result:**
Reduces accidental deletions.

### Navigation After Deletion

**Scenario 1: Delete from grid**
- User on `/projets`
- Deletes project
- Stays on `/projets`
- Card disappears

**Scenario 2: Delete from detail page**
- User on `/projets/123`
- Deletes project
- Redirects to `/projets`
- Toast: "Projet supprimé"

**Implementation:**
```typescript
if (window.location.pathname.includes(`/projets/${projectId}`)) {
  router.push('/projets')
}
```

### Rollback User Experience

**Failure scenario:**
1. User clicks delete
2. Confirmation modal
3. Confirms
4. Card disappears (optimistic)
5. API fails (network error)
6. Card reappears (rollback)
7. Error toast

**User confusion:**
"Why did it come back?"

**Mitigation:**
Clear error message:
"Impossible de supprimer le projet. Veuillez réessayer."

### Backend Transaction Safety

**Why transaction?**
```typescript
const trx = await Database.transaction()

// Delete project
// Cascade delete tasks

await trx.commit() // Both succeed
// OR
await trx.rollback() // Both fail
```

**Without transaction:**
- Project deleted
- Task cascade fails
- Orphaned project (deleted) with active tasks
- Data inconsistency

**With transaction:**
- Both succeed OR both fail
- Atomic operation
- Data integrity maintained

### Error Handling Edge Cases

**Scenario 1: Network error during delete**
- Optimistic update shows project gone
- API call fails (offline)
- Rollback: project reappears
- User sees error toast

**Scenario 2: Project deleted by another session**
- User A has project open
- User B (same account, different device) deletes project
- User A tries to delete
- API returns 404
- Rollback not needed (already gone)
- Show: "Project already deleted"

**Scenario 3: Partial cascade failure**
- Transaction prevents this
- If task delete fails, project delete also fails
- Rollback ensures consistency

### Performance Considerations

**Cascade delete 100 tasks:**
```sql
UPDATE tasks SET deleted_at = NOW() WHERE project_id = 'xyz'
```

Single SQL query, efficient.

**Alternative (slower):**
```typescript
for (const task of tasks) {
  await task.delete()
}
```

Avoid N+1 queries. Use bulk update.

### Cache Invalidation Timing

**When to invalidate:**
After successful delete, invalidate:
1. `['projects']` - Grid needs update
2. `['today']` - Today needs update

**Don't invalidate project detail:**
User already navigated away (if on detail page).

**Alternative:**
Remove queries explicitly:
```typescript
queryClient.removeQueries(['projects', projectId])
```

Prevents 404 refetch.

### Toast Notification Timing

**Success toast:**
"Projet supprimé avec succès"

Show after:
1. API succeeds
2. Navigation complete (if from detail page)

**Error toast:**
"Impossible de supprimer le projet. Veuillez réessayer."

Show after:
1. API fails
2. Rollback complete

**Duration:**
- Success: 3 seconds
- Error: 5 seconds (user needs time to read and retry)

Cascade restore.
