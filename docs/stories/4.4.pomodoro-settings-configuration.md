# Story 4.4: Pomodoro Settings Configuration

**Epic:** 4 - Pomodoro Timer (Focused Execution Tool)
**Story Number:** 4.4
**Status:** Ready for Review

---

## Story

**As a** user,
**I want** to customize Pomodoro durations,
**so that** I can adapt the technique to my work style.

---

## Acceptance Criteria

1. Settings icon opens modal
2. Modal fields: focus duration (1-60min), break duration (1-30min), repetitions (1-10), auto-switch toggle
3. Save updates pomodoroStore.settings, persists to backend
4. Backend: User.pomodoro_settings JSONB, PATCH /v1/users/me/pomodoro-settings
5. Settings fetched from GET /v1/users/me on load
6. Changing while running shows warning: "Changing settings will reset timer. Continue?"
7. Confirmed change stops timer, applies settings
8. Modal pre-fills current values
9. Validation: positive integers within range, repetitions >= 1
10. Keyboard: "," opens settings
11. Settings synced via API
12. Unit tests for persistence and reset

### Task 3: Create Backend Endpoint for Settings (AC: 4, 5)

- [x] Update `apps/api/app/Controllers/Http/UsersController.ts`:
  ```typescript
  import type { HttpContextContract } from '@ioc:Adonis/Core/HttpContext'
  import User from 'App/Models/User'

  export default class UsersController {
    // AC 5: Get user with settings
    public async me({ auth, response }: HttpContextContract) {
      const user = auth.user!
      return response.ok({
        id: user.id,
        email: user.email,
        name: user.name,
        pomodoro_settings: user.pomodoro_settings,
      })
    }

    // AC 4: Update Pomodoro settings
    public async updatePomodoroSettings({
      auth,
      request,
      response,
    }: HttpContextContract) {
      const user = auth.user!
      const settings = request.only([
        'focusDuration',
        'breakDuration',
        'repetitions',
        'autoSwitch',
      ])

      // Validate
      if (
        settings.focusDuration < 1 ||
        settings.focusDuration > 60 ||
        settings.breakDuration < 1 ||
        settings.breakDuration > 30 ||
        settings.repetitions < 1 ||
        settings.repetitions > 10
      ) {
        return response.badRequest({ message: 'Invalid settings values' })
      }

      // AC 4: Update JSONB field
      user.pomodoro_settings = settings
      await user.save()

      return response.ok(user.pomodoro_settings)
    }
  }
  ```

### Task 4: Create useUpdatePomodoroSettings Hook (AC: 3, 11)

- [x] Create `apps/web/hooks/useUpdatePomodoroSettings.ts`:
  ```typescript
  import { useMutation, useQueryClient } from '@tanstack/react-query'
  import { userService } from '@/services/userService'
  import type { PomodoroSettings } from '@focus-guide/shared'
  import { toast } from '@/hooks/use-toast'

  export function useUpdatePomodoroSettings() {
    const queryClient = useQueryClient()

    return useMutation({
      mutationFn: (settings: PomodoroSettings) =>
        userService.updatePomodoroSettings(settings),

      onSuccess: () => {
        // AC 11: Sync via API
        queryClient.invalidateQueries({ queryKey: ['user', 'me'] })

        toast({
          title: 'Succès',
          description: 'Paramètres Pomodoro enregistrés',
        })
      },

      onError: () => {
        toast({
          title: 'Erreur',
          description: 'Impossible de sauvegarder les paramètres',
          variant: 'destructive',
        })
      },
    })
  }
  ```

### Task 5: Fetch Settings on Load (AC: 5)

- [x] Create `apps/web/hooks/useLoadPomodoroSettings.ts`:
  ```typescript
  import { useEffect } from 'react'
  import { useQuery } from '@tanstack/react-query'
  import { userService } from '@/services/userService'
  import { usePomodoroStore } from '@/stores/pomodoroStore'

  export function useLoadPomodoroSettings() {
    const { data: user } = useQuery({
      queryKey: ['user', 'me'],
      queryFn: () => userService.getMe(),
    })

    const { updateSettings } = usePomodoroStore()

    // AC 5: Load settings from backend
    useEffect(() => {
      if (user?.pomodoro_settings) {
        updateSettings(user.pomodoro_settings)
      }
    }, [user, updateSettings])
  }
  ```

## Dev Notes

### Settings Storage (AC 3, 4)

**Frontend: Zustand + localStorage**
**Backend: PostgreSQL JSONB**

**Sync:**
1. User changes settings
2. Update Zustand store (instant)
3. PATCH /v1/users/me/pomodoro-settings (background)
4. On load: GET /v1/users/me → restore from backend

**Why both?**
- localStorage: Offline access
- Backend: Sync across devices

### JSONB Column (AC 4)

**Flexible schema:**
```sql
pomodoro_settings JSONB DEFAULT '{"focusDuration":25,...}'
```

**Benefits:**
- Add fields without migration
- Store complex structure
- Query with JSON operators

### Validation Ranges (AC 2, 9)

**Focus: 1-60 min**
- Min: 1 min (too short below)
- Max: 60 min (1 hour, reasonable)

**Break: 1-30 min**
- Min: 1 min
- Max: 30 min (longer break = different technique)

**Repetitions: 1-10**
- Min: 1 cycle
- Max: 10 cycles (4+ hours, enough)

### Warning Dialog (AC 6, 7)

**Why warn?**
Changing settings resets timer.

**Scenario:**
User 15 min into focus, changes duration.

**Without warning:**
Loses progress (frustrating).

**With warning:**
User decides: Continue or cancel.
