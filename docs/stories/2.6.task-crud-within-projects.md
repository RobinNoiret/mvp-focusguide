# Story 2.6: Task CRUD Within Projects

**Epic:** 2 - Projects Management (Strategic Planning Layer)
**Story Number:** 2.6
**Status:** Draft

---

## Story

**As a** user,
**I want** to create, edit, and delete tasks within a project,
**so that** I can build out my project's task list.

---

## Acceptance Criteria

1. "Add task" opens modal
2. Modal fields: title, notes, project_status (pre-filled), project_id (hidden)
3. Create calls POST /v1/tasks with project_id, project_status, today_status null
4. Task appears optimistically
5. Edit icon opens modal (title, notes editable)
6. Save calls PATCH, updates optimistically
7. Delete icon shows confirmation
8. Confirm calls DELETE, removes optimistically
9. Drag-drop between columns updates project_status
10. "Done" column checks checkbox
11. Optimistic updates with rollback
12. React Query invalidates useProject(id) cache
13. Unit tests for task CRUD

### Task 4: Create useCreateProjectTask Hook (AC: 3, 4, 11, 12)

- [ ] Create `apps/web/hooks/useCreateProjectTask.ts`:
  ```typescript
  import { useMutation, useQueryClient } from '@tanstack/react-query'
  import { taskService } from '@/services/taskService'
  import type { CreateTaskInput, Task, ProjectWithStats } from '@focus-guide/shared'
  import { toast } from '@/hooks/use-toast'

  export function useCreateProjectTask(projectId: string) {
    const queryClient = useQueryClient()

    return useMutation({
      mutationFn: (input: CreateTaskInput) => taskService.createTask(input),

      // AC 4, 11: Optimistic update
      onMutate: async (newTask) => {
        // Cancel outgoing queries
        await queryClient.cancelQueries({ queryKey: ['projects', projectId] })

        // Snapshot previous value
        const previousProject = queryClient.getQueryData<ProjectWithStats>([
          'projects',
          projectId,
        ])

        // Optimistically add task to project
        queryClient.setQueryData<ProjectWithStats>(
          ['projects', projectId],
          (old) => {
            if (!old) return old

            const optimisticTask: Task = {
              id: `temp-${Date.now()}`,
              user_id: 'current-user',
              project_id: newTask.project_id || null,
              title: newTask.title,
              notes: newTask.notes || null,
              today_status: newTask.today_status || null,
              project_status: newTask.project_status || null,
              created_at: new Date().toISOString(),
              updated_at: new Date().toISOString(),
              deleted_at: null,
            }

            return {
              ...old,
              tasks: [...(old.tasks || []), optimisticTask],
              task_count: old.task_count + 1,
              task_counts: {
                ...old.task_counts,
                [newTask.project_status as string]:
                  (old.task_counts?.[newTask.project_status as keyof typeof old.task_counts] || 0) + 1,
              },
            }
          }
        )

        return { previousProject }
      },

      // AC 11: Rollback on error
      onError: (err, variables, context) => {
        queryClient.setQueryData(
          ['projects', projectId],
          context?.previousProject
        )

        toast({
          title: 'Erreur',
          description: 'Impossible de créer la tâche. Veuillez réessayer.',
          variant: 'destructive',
        })
      },

      // AC 12: Invalidate useProject(id) cache
      onSuccess: () => {
        queryClient.invalidateQueries({ queryKey: ['projects', projectId] })

        toast({
          title: 'Succès',
          description: 'Tâche créée avec succès',
        })
      },
    })
  }
  ```

### Task 5: Create useUpdateProjectTask Hook (AC: 6, 9, 10, 11, 12)

  ```typescript
  import { useMutation, useQueryClient } from '@tanstack/react-query'
  import { taskService } from '@/services/taskService'
  import type { UpdateTaskInput, Task, ProjectWithStats, ProjectStatus } from '@focus-guide/shared'
  import { toast } from '@/hooks/use-toast'

  export function useUpdateProjectTask(projectId: string) {
    const queryClient = useQueryClient()

    return useMutation({
      mutationFn: ({ id, data }: { id: string; data: UpdateTaskInput }) =>
        taskService.updateTask(id, data),

      // AC 6, 9, 10, 11: Optimistic update
      onMutate: async ({ id, data }) => {
        await queryClient.cancelQueries({ queryKey: ['projects', projectId] })

        const previousProject = queryClient.getQueryData<ProjectWithStats>([
          'projects',
          projectId,
        ])

        // Optimistically update task
        queryClient.setQueryData<ProjectWithStats>(
          ['projects', projectId],
          (old) => {
            if (!old) return old

            const updatedTasks = old.tasks?.map((task) => {
              if (task.id !== id) return task

              // AC 10: Done column checks checkbox
              const newProjectStatus = data.project_status || task.project_status
              const isDone = newProjectStatus === 'done'

              return {
                ...task,
                title: data.title ?? task.title,
                notes: data.notes ?? task.notes,
                project_status: newProjectStatus,
                updated_at: new Date().toISOString(),
              }
            })

            // Recalculate task counts
            const taskCounts = { backlog: 0, todo: 0, in_progress: 0, done: 0 }
            updatedTasks?.forEach((task) => {
              if (task.project_status) {
                taskCounts[task.project_status as ProjectStatus]++
              }
            })

            const doneCount = taskCounts.done
            const totalCount = updatedTasks?.length || 0
            const completionPercentage =
              totalCount === 0 ? 0 : Math.round((doneCount / totalCount) * 100)

            return {
              ...old,
              tasks: updatedTasks,
              task_counts: taskCounts,
              completion_percentage: completionPercentage,
            }
          }
        )

        return { previousProject }
      },

      // AC 11: Rollback on error
      onError: (err, variables, context) => {
        queryClient.setQueryData(
          ['projects', projectId],
          context?.previousProject
        )

        toast({
          title: 'Erreur',
          description: 'Impossible de modifier la tâche. Veuillez réessayer.',
          variant: 'destructive',
        })
      },

      // AC 12: Invalidate cache
      onSuccess: () => {
        queryClient.invalidateQueries({ queryKey: ['projects', projectId] })

        toast({
          title: 'Succès',
          description: 'Tâche modifiée avec succès',
        })
      },
    })
  }
  ```

  ```typescript
  'use client'

  import { useMemo, useState } from 'react'
  import {
    DndContext,
    DragOverlay,
    closestCorners,
    KeyboardSensor,
    PointerSensor,
    useSensor,
    useSensors,
    DragStartEvent,
    DragEndEvent,
  } from '@dnd-kit/core'
  import { arrayMove, SortableContext } from '@dnd-kit/sortable'
  import { ProjectTaskCard } from './ProjectTaskCard'
  import { DroppableColumn } from './DroppableColumn'

  import type { ProjectWithStats, Task, ProjectStatus } from '@focus-guide/shared'

  export function ProjectKanban({ project }: { project: ProjectWithStats }) {
    const [activeTask, setActiveTask] = useState<Task | null>(null)
    const updateTask = useUpdateProjectTask(project.id)

    // Configure sensors
    const sensors = useSensors(
      useSensor(PointerSensor),
      useSensor(KeyboardSensor)
    )

    // Group tasks by status
    const tasksByStatus = useMemo(() => {
      const groups: Record<ProjectStatus, Task[]> = {
        backlog: [],
        todo: [],
        in_progress: [],
        done: [],
      }

      project.tasks?.forEach((task) => {
        if (task.project_status && !task.deleted_at) {
          groups[task.project_status as ProjectStatus].push(task)
        }
      })

      return groups
    }, [project.tasks])

    const handleDragStart = (event: DragStartEvent) => {
      const { active } = event
      const task = project.tasks?.find((t) => t.id === active.id)
      setActiveTask(task || null)
    }

    const handleDragEnd = async (event: DragEndEvent) => {
      const { active, over } = event

      setActiveTask(null)

      if (!over) return

      const taskId = active.id as string
      const newStatus = over.id as ProjectStatus

      const task = project.tasks?.find((t) => t.id === taskId)
      if (!task) return

      // AC 9: Drag-drop updates project_status
      if (task.project_status !== newStatus) {
        await updateTask.mutateAsync({
          id: taskId,
          data: { project_status: newStatus },
        })
      }
    }

    const columns: Array<{
      id: ProjectStatus
      title: string
      tasks: Task[]
    }> = [
      { id: 'backlog', title: 'Backlog', tasks: tasksByStatus.backlog },
      { id: 'todo', title: 'To do', tasks: tasksByStatus.todo },
      { id: 'in_progress', title: 'In progress', tasks: tasksByStatus.in_progress },
      { id: 'done', title: 'Done', tasks: tasksByStatus.done },
    ]

    return (
      <DndContext
        sensors={sensors}
        collisionDetection={closestCorners}
        onDragStart={handleDragStart}
        onDragEnd={handleDragEnd}
      >
        <div className="flex gap-6">
          {columns.slice(0, 3).map((column) => (
            <DroppableColumn
              key={column.id}
              column={column}
              projectId={project.id}
              vertical={false}
            />
          ))}
          <DroppableColumn
            column={columns[3]}
            projectId={project.id}
            vertical={true}
          />
        </div>

        <DragOverlay>
          {activeTask && (
            <ProjectTaskCard
              task={activeTask}
              projectId={project.id}
              isDragging
            />
          )}
        </DragOverlay>
      </DndContext>
    )
  }
  ```

## Dev Notes

### Task Creation Flow

**User flow:**
1. Click "+" button in column header
2. Modal opens with column pre-selected
3. Enter title (required) and notes (optional)
4. Click "Créer la tâche"
5. Task appears in column immediately (optimistic)
6. Background API call creates task on server
7. On success: Replace temp ID with real ID
8. On error: Remove task, show error toast

**Pre-filled fields:**
```typescript
project_id: projectId // Hidden
project_status: columnId // Pre-filled (backlog, todo, in_progress, done)
today_status: null // Not in Today yet (Story 3.4)
```

**Why pre-fill project_status?**
- User clicked "+" in specific column → intent is clear
- Saves user from dropdown selection
- Faster workflow

### Edit vs Update Task Status

**Two types of updates:**
1. **Edit modal:** Title and notes (text fields)
2. **Drag-drop:** project_status (column change)

**Why separate?**
- Different UX patterns (modal vs drag)
- Different fields updated
- Both use same PATCH endpoint

**Backend PATCH /v1/tasks/:id:**
```json
{
  "title": "Updated title", // From edit modal
  "notes": "Updated notes"  // From edit modal
}
```

OR

```json
{
  "project_status": "in_progress" // From drag-drop
}
```

Partial update (only send changed fields).

### Checkbox Toggles Done Status (AC 10)

**Behavior:**
- Unchecked → Click → Status becomes 'done'
- Checked → Click → Status reverts to previous (or 'todo')

**Implementation challenge:**
Current: `task.project_status === 'done'`
Revert to: What was previous status?

**Solution 1: Toggle to 'todo'**
```typescript
const newStatus = isChecked ? 'todo' : 'done'
```

**Solution 2: Store previous status**
```typescript
const prevStatus = task.metadata?.previousStatus || 'todo'
const newStatus = isChecked ? prevStatus : 'done'
```

For MVP: Toggle to 'todo' (simpler). User can drag if needed.

### Optimistic Update Complexity

**Three mutations, three optimistic updates:**
1. Create: Add task to array
2. Update: Modify task in array
3. Delete: Remove task from array

**All must:**
- Update `tasks` array
- Recalculate `task_counts` (backlog, todo, in_progress, done)
- Recalculate `completion_percentage`
- Update `task_count`

**Challenge: Consistency**
If optimistic calculation differs from server, data out of sync.

**Mitigation:**
- Invalidate cache after mutation
- Server refetch provides authoritative data
- Optimistic update just for UX (feels instant)

### Drag-and-Drop Implementation

**dnd-kit advantages:**
- ✅ Accessibility (keyboard, screen reader)
- ✅ Touch support (mobile, tablet)
- ✅ Customizable (sensors, collision detection)
- ✅ TypeScript support

**Key concepts:**
- **DndContext:** Manages drag state
- **Droppable:** Drop zone (columns)
- **Draggable/Sortable:** Draggable items (tasks)
- **DragOverlay:** Visual feedback during drag

**Sensors:**
```typescript

```

**Collision detection:**

### Task Counts Recalculation

**Every mutation must update counts:**
```typescript
const taskCounts = { backlog: 0, todo: 0, in_progress: 0, done: 0 }
updatedTasks.forEach(task => {
  if (task.project_status) {
    taskCounts[task.project_status]++
  }
})
```

**Completion percentage:**
```typescript
const doneCount = taskCounts.done
const totalCount = updatedTasks.length
const percentage = totalCount === 0 ? 0 : Math.round((doneCount / totalCount) * 100)
```

**Why recalculate?**
Server does same calculation. Optimistic update must match to avoid flicker.

### Rollback Strategy

**Rollback on API failure:**
```typescript
onError: (err, variables, context) => {
  queryClient.setQueryData(['projects', projectId], context.previousProject)
}
```

**previousProject snapshot:**
Captured in `onMutate` before optimistic update.

**User experience:**
1. Task appears (optimistic)
2. API fails (network error, validation error)
3. Task disappears (rollback)
4. Error toast: "Impossible de créer la tâche"

User sees smooth UX even on failure.

### Cache Invalidation Timing

**When to invalidate:**
- After successful mutation (not before)
- Invalidate `['projects', projectId]` (single project)
- Also invalidate `['projects']` (grid view needs updated counts)

**Why both?**
- User on detail page → sees immediate update
- User navigates to grid → sees updated completion %

**Alternative: Update both caches optimistically**
More complex, fewer API calls. Can optimize later.

- API fails (validation error)
- Task rolls back to original column
- User sees error toast

**Scenario 3: Delete fails**
- User deletes task
- Task removed optimistically
- API fails
- Task reappears
- User confused (why did it come back?)

**Mitigation:**
Clear error messages: "La tâche n'a pas pu être supprimée. Veuillez réessayer."
