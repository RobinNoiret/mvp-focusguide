# Story 3.6: Bidirectional Sync (Project → Today)

**Epic:** 3 - Connection Layer (Bridge Projects and Today with Bidirectional Sync)
**Story Number:** 3.6
**Status:** Draft

---

## Story

**As a** user,
**I want** Project status changes to update Today,
**so that** Today board reflects current project status.

---

## Acceptance Criteria

1. Task with today_status moved to Done in Project → today_status: done
2. TaskSyncService extended: project_status=done → today_status=done (if today_status exists)
3. Task marked done in Project shows done in Today
4. React Query invalidates both caches
5. Sync works bidirectionally
6. Unit test: project task → Today → mark done in Project → verify today_status
7. Integration test: E2E flow
8. Edge case: task removed from Today (today_status null) → no sync to Today
9. Edge case: task removed from Project (project_id null) → no sync to Project
10. Documentation explaining bidirectional sync

### Task 1: Extend TaskSyncService for Project → Today (AC: 2)

- [ ] Update `apps/api/app/Services/TaskSyncService.ts`:
  ```typescript
  import Task from 'App/Models/Task'
  import type { TodayStatus, ProjectStatus } from '@focus-guide/shared'

  export class TaskSyncService {
    /**
     * AC 2, 5: Bidirectional sync logic
     */
    public static async applyBidirectionalSync(task: Task): Promise<void> {
      // Story 3.5: Today → Project
      // AC 2: today_status=done → project_status=done
      if (task.today_status === 'done' && task.project_id) {
        task.project_status = 'done'
      }

      // Story 3.6: Project → Today
      // AC 2: project_status=done → today_status=done
      if (task.project_status === 'done' && task.today_status) {
        task.today_status = 'done'
      }

      // AC 8, 9: Edge cases
      // If task removed from Today (today_status = null), don't sync to Today
      // If task removed from Project (project_id = null), don't sync to Project

      await task.save()
    }

    /**
     * Check if sync should occur
     */
    private static shouldSync(task: Task): boolean {
      // AC 8: No sync if task not in Today
      if (!task.today_status && task.project_status === 'done') {
        return false
      }

      // AC 9: No sync if task not in Project
      if (!task.project_id && task.today_status === 'done') {
        return false
      }

      return true
    }
  }
  ```

### Task 7: Create Documentation for Bidirectional Sync (AC: 10)

- [ ] Create `docs/architecture/bidirectional-sync.md`:
  ```markdown
  # Bidirectional Sync: Projects ↔ Today

  ## Overview

  Focus Guide's core differentiator is the connection layer that allows tasks to exist in both Project kanbans and the Today board simultaneously. When a task's status changes in one context, it automatically syncs to the other.

  ## Sync Rules

  ### Today → Project

  When a task is marked **done** in Today:
  - If task has `project_id` (belongs to a project)
  - Then `project_status` is set to **done**

  ### Project → Today

  When a task is marked **done** in a Project:
  - If task has `today_status` (exists in Today)
  - Then `today_status` is set to **done**

  ## Edge Cases

  ### Task Not in Today

  - Task exists only in Project
  - User marks done in Project
  - **No sync to Today** (task not there)

  ### Task Not in Project

  - Standalone task in Today only
  - User marks done in Today
  - **No sync to Project** (no project)

  ### Task Removed from Today

  - Task initially in both contexts
  - User removes from Today (`today_status = null`)
  - Future Project updates **do not sync to Today**

  ### Task Removed from Project

  - Task initially in both contexts
  - Project deleted (cascade sets `project_id = null`)
  - Future Today updates **do not sync to Project**

  ## Implementation

  ### Backend: TaskSyncService

  Located: `apps/api/app/Services/TaskSyncService.ts`

  ```typescript
  public static async applyBidirectionalSync(task: Task): Promise<void> {
    // Today → Project
    if (task.today_status === 'done' && task.project_id) {
      task.project_status = 'done'
    }

    // Project → Today
    if (task.project_status === 'done' && task.today_status) {
      task.today_status = 'done'
    }

    await task.save()
  }
  ```

  Called in `TasksController.update()` before returning response.

  ### Frontend: Cache Invalidation

  Both caches must be invalidated on task update:

  ```typescript
  queryClient.invalidateQueries(['today'])
  queryClient.invalidateQueries(['projects', projectId])
  ```

  This ensures both views refetch and display updated status.

  ## Future Enhancements

  ### Sync All Statuses

  Currently only **done** syncs. Future could sync:
  - `in_progress` → `in_progress`
  - `todo` → `todo`

  ### Configurable Sync

  User preference:
  - "Auto-sync Projects and Today" (default: on)
  - "Manual sync only"

  ### Conflict Resolution

  What if user marks done in Today, then marks todo in Project simultaneously?
  - Server uses "last write wins"
  - Potential enhancement: Conflict detection + user prompt

  ## Testing

  - Unit tests: `apps/api/tests/unit/services/TaskSyncService.spec.ts`
  - Integration tests: `apps/web/tests/e2e/bidirectional-sync.spec.ts`
  - Coverage: Both sync directions + edge cases

## Dev Notes

### Sync Symmetry (AC 2, 5)

**Bidirectional means:**
```
Today → Project: done → done
Project → Today: done → done
```

**Symmetric logic:**
Same rule applies in both directions.

**Easy to reason about.**

### Why Only "Done"? (AC 2)

**MVP scope:**
- Most critical status
- Clear completion signal
- Reduces complexity

**Future:**
```typescript
// Sync all statuses
const statusMap = {
  backlog: 'backlog',
  todo: 'todo',
  in_progress: 'in_progress',
  done: 'done',
}
```

**Challenge:**
Today and Project have different status names.

**For MVP:**
Only "done" is universal.

### Cache Invalidation Importance (AC 4)

**Without invalidation:**
```
User marks done in Project
Backend syncs today_status
Frontend Today cache stale
Today shows old status ❌
```

**With invalidation:**
```
User marks done in Project
Backend syncs today_status
Frontend invalidates both caches
Both refetch
Both show updated status ✅
```

**Critical for UX.**

### Edge Case: Removed from Today (AC 8)

**Scenario:**
1. Task in both Project and Today
2. User drags out of Today (removes)
3. `today_status = null`
4. User marks done in Project
5. Should Today update? **No.**

**Why?**
Task no longer in Today (user removed it).

**Implementation:**
```typescript
if (task.project_status === 'done' && task.today_status) {
  // Only sync if task.today_status exists
}
```

### Edge Case: Removed from Project (AC 9)

**Scenario:**
1. Task in both contexts
2. Project deleted (cascade)
3. `project_id = null`
4. User marks done in Today
5. Should Project update? **No.**

**Why?**
Task no longer belongs to project.

**Implementation:**
```typescript
if (task.today_status === 'done' && task.project_id) {
  // Only sync if task.project_id exists
}
```

### Performance: Double Write

**Concern:**
Sync requires two DB writes:
```sql
UPDATE tasks SET today_status = 'done' WHERE id = ?
UPDATE tasks SET project_status = 'done' WHERE id = ?
```

**Actually:**
Single write with both fields:
```sql
UPDATE tasks SET today_status = 'done', project_status = 'done' WHERE id = ?
```

**TaskSyncService:**
Modifies task object, then single `task.save()`.

**Efficient.**

### Conflict Scenarios

**Scenario:**
1. User A marks done in Today
2. User B marks todo in Project (different device)
3. Which wins?

**Current:**
Last write wins (database timestamp).

**Future enhancement:**
- Detect conflicts
- Prompt user: "Conflict detected. Choose status."

**Not in MVP.**

### Reverse Sync: Undoing

**Question:**
What if user unchecks in Project?

**Current behavior:**
```typescript
task.project_status = 'todo'
// Does NOT reverse sync to Today
```

**Future:**
```typescript
if (task.project_status !== 'done' && task.today_status === 'done') {
  task.today_status = 'todo' // Reverse sync
}
```

**Complexity:**
Which status should it revert to?

**For MVP:**
Only sync "done", not reverse.
