# Story 1.4: Email Verification Flow

**Epic:** 1 - Foundation & Today Page
**Story Number:** 1.4
**Status:** Draft

---

## Story

**As a** registered user,
**I want** to verify my email address,
**so that** I can access full application features.

---

## Acceptance Criteria

1. Registration creates user with email_verified: false
2. Verification token generated (UUID, 24h expiry) and stored
3. Verification email sent with link
4. POST /v1/auth/verify-email validates token, marks user verified
5. Email verification page reads token from query params, calls API
6. Unverified users see banner with resend button
7. POST /v1/auth/resend-verification (rate limited: 3/hour)
8. Verified users have full access
9. Unit tests for token generation, validation, expiry

  ```typescript
  import { randomUUID } from 'node:crypto'
  import { DateTime } from 'luxon'
  import User from '#models/User'
  import VerificationToken from '#models/VerificationToken'
  import { emailService } from '#services/email_service'
  import { registerValidator } from '#validators/auth_validator'
  import type { HttpContext } from '@adonisjs/core/http'

  export default class AuthController {
    async register({ request, response }: HttpContext) {
      const data = await request.validateUsing(registerValidator)

      // Check if user exists
      const existingUser = await User.findBy('email', data.email)
      if (existingUser) {
        return response.conflict({ error: 'Email already registered' })
      }

      // Create user with emailVerified: false
      const user = await User.create({
        email: data.email,
        password: data.password,
        name: data.name,
        emailVerified: false, // AC: 1
        pomodoroSettings: {
          focusDuration: 25,
          breakDuration: 5,
          repetitions: 3,
          autoSwitch: false,
        },
      })

      // Generate verification token (AC: 2)
      const token = randomUUID()
      const expiresAt = DateTime.now().plus({ hours: 24 })

      await VerificationToken.create({
        userId: user.id,
        token,
        type: 'email_verification',
        expiresAt,
      })

      // Send verification email (AC: 3)
      try {
        await emailService.sendVerificationEmail(user, token)
      } catch (error) {
        console.error('Failed to send verification email:', error)
        // Don't fail registration if email fails
      }

      return response.created({
        id: user.id,
        email: user.email,
        name: user.name,
        emailVerified: user.emailVerified,
      })
    }

    // Existing login, logout, refresh methods...
  }
  ```

- [ ] Implement `verifyEmail` method in AuthController:
  ```typescript
  async verifyEmail({ request, response }: HttpContext) {
    const { token } = await request.validateUsing(verifyEmailValidator)

    // Find token
    const verificationToken = await VerificationToken.query()
      .where('token', token)
      .where('type', 'email_verification')
      .preload('user')
      .first()

    if (!verificationToken) {
      return response.badRequest({ error: 'Invalid verification token' })
    }

    // Check expiry
    if (verificationToken.isExpired()) {
      await verificationToken.delete()
      return response.badRequest({ error: 'Verification token expired' })
    }

    // Mark user as verified
    verificationToken.user.emailVerified = true
    await verificationToken.user.save()

    // Delete token (one-time use)
    await verificationToken.delete()

    return response.ok({
      message: 'Email verified successfully',
      user: {
        id: verificationToken.user.id,
        email: verificationToken.user.email,
        name: verificationToken.user.name,
        emailVerified: verificationToken.user.emailVerified,
      },
    })
  }
  ```

### Task 7: Create POST /v1/auth/resend-verification Endpoint (AC: 7)

- [ ] Implement `resendVerification` method in AuthController:
  ```typescript
  async resendVerification({ auth, response }: HttpContext) {
    const user = auth.user!

    // Check if already verified
    if (user.emailVerified) {
      return response.badRequest({ error: 'Email already verified' })
    }

    // Delete old tokens
    await VerificationToken.query()
      .where('user_id', user.id)
      .where('type', 'email_verification')
      .delete()

    // Generate new token
    const token = randomUUID()
    const expiresAt = DateTime.now().plus({ hours: 24 })

    await VerificationToken.create({
      userId: user.id,
      token,
      type: 'email_verification',
      expiresAt,
    })

    // Send email
    try {
      await emailService.sendVerificationEmail(user, token)
    } catch (error) {
      console.error('Failed to send verification email:', error)
      return response.internalServerError({ error: 'Failed to send email' })
    }

    return response.ok({ message: 'Verification email sent' })
  }
  ```

### Task 10: Enforce Email Verification on Protected Endpoints (AC: 8)

  ```typescript
  import type { HttpContext } from '@adonisjs/core/http'
  import type { NextFn } from '@adonisjs/core/types/http'

  export default class RequireVerifiedEmailMiddleware {
    async handle({ auth, response }: HttpContext, next: NextFn) {
      const user = auth.user

      if (!user) {
        return response.unauthorized({ error: 'Unauthorized' })
      }

      if (!user.emailVerified) {
        return response.forbidden({
          error: 'Email verification required',
          code: 'EMAIL_NOT_VERIFIED',
        })
      }

      return await next()
    }
  }
  ```

### Verification Flow Architecture

[Source: docs/architecture.md#Email Verification, Lines 264-270]

**Backend Flow:**
1. User registers → User created with `emailVerified: false`
2. Generate UUID token with 24h expiry → Store in `verification_tokens` table
3. Send email with verification link: `{FRONTEND_URL}/verify-email?token={uuid}`
4. User clicks link → Frontend calls `POST /v1/auth/verify-email` with token
5. Backend validates token → Mark user as verified → Delete token

**Security Considerations:**
- Tokens are UUIDs (cryptographically random, impossible to guess)
- 24-hour expiry window
- One-time use (deleted after verification)
- Rate limiting on resend (3 requests/hour)

### Database Schema

**verification_tokens table:**
```sql
CREATE TABLE verification_tokens (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token VARCHAR NOT NULL UNIQUE,
  type ENUM('email_verification', 'password_reset') NOT NULL,
  expires_at TIMESTAMP NOT NULL,
  created_at TIMESTAMP NOT NULL,
  INDEX(token),
  INDEX(user_id),
  INDEX(expires_at, type)
);
```

**Why separate table?**
- Supports multiple token types (email verification, password reset)
- Easy to clean up expired tokens with scheduled job
- Prevents user table bloat

### Security Best Practices

**Email Enumeration Prevention:**
- Don't reveal if email exists in "resend" endpoint
- Generic success message: "Email sent if account exists"

**Token Security:**
- UUIDs are cryptographically secure (128-bit randomness)
- Stored in database (not JWT - can't be revoked)
- Single-use prevents replay attacks

**HTTPS Only:**
- Verification links use HTTPS in production
- Prevents token interception

```typescript
export default class CleanupExpiredTokens {
```
