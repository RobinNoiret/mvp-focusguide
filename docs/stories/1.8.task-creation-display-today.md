# Story 1.8: Task Creation & Display in Today

**Epic:** 1 - Foundation & Today Page (Standalone Daily Task Management)
**Story Number:** 1.8
**Status:** In Progress

---

## Story

**As a** user,
**I want** to create tasks and see them in my Today board,
**so that** I can start organizing my daily work.

---

## Acceptance Criteria

1. POST /v1/tasks creates task (title, notes, today_status, project_id null)
2. GET /v1/today returns tasks where today_status NOT NULL, grouped by status
3. "Add task" button in each column opens creation modal
4. Modal has title (required), notes (textarea)
5. Task created in specific column sets today_status to that column
6. Optimistic update: task appears immediately
7. Background API call creates on server
8. Task card displays: checkbox, title, notes preview, edit/delete icons
9. Cards styled per mockup (chartreuse 10% background)
10. Tasks in chronological order (recent first)
11. React Query invalidates cache on success
12. Error handling: remove optimistic task on failure
13. Unit tests for creation

### Task 6: Frontend - React Query Hooks (AC: 6, 7, 11, 12)

- [x] Create `apps/web/src/hooks/useTodayTasks.ts`:
  ```typescript
  import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query'
  import { taskService } from '@/services/taskService'
  import type { Task, CreateTaskInput } from '@focus-guide/shared'

  // Fetch today tasks
  export function useTodayTasks() {
    return useQuery({
      queryKey: ['today', 'tasks'],
      queryFn: () => taskService.getTodayTasks(),
      staleTime: 30000, // 30 seconds
    })
  }

  // Create task with optimistic update
  export function useCreateTask() {
    const queryClient = useQueryClient()

    return useMutation({
      mutationFn: (input: CreateTaskInput) => taskService.createTask(input),

      // AC 6: Optimistic update
      onMutate: async (newTask) => {
        await queryClient.cancelQueries({ queryKey: ['today', 'tasks'] })

        const previousTasks = queryClient.getQueryData<Task[]>(['today', 'tasks'])

        // Optimistically add task
        const optimisticTask: Task = {
          id: `temp-${Date.now()}`, // Temporary ID
          user_id: 'current-user',
          title: newTask.title,
          notes: newTask.notes || null,
          today_status: newTask.today_status || 'todo',
          project_id: null,
          project_status: null,
          created_at: new Date().toISOString(),
          updated_at: new Date().toISOString(),
          deleted_at: null,
        }

        queryClient.setQueryData<Task[]>(['today', 'tasks'], (old) =>
          [optimisticTask, ...(old || [])]
        )

        return { previousTasks }
      },

      // AC 12: Error handling - rollback on failure
      onError: (err, newTask, context) => {
        queryClient.setQueryData(['today', 'tasks'], context?.previousTasks)
        // Show error toast
      },

      // AC 11: Invalidate cache on success
      onSuccess: () => {
        queryClient.invalidateQueries({ queryKey: ['today', 'tasks'] })
      },
    })
  }
  ```

### Task Status Enum Values

[Source: docs/prd.md#Story 1.2 + Database Schema]

**Today Status Enum:**
- `'backlog'` - Tasks planned but not for today
- `'todo'` - Tasks scheduled for today
- `'in_progress'` - Tasks currently being worked on
- `'done'` - Completed tasks

**Database Column Type:**
```sql
CREATE TYPE today_status_enum AS ENUM ('backlog', 'todo', 'in_progress', 'done');
ALTER TABLE tasks ADD COLUMN today_status today_status_enum;
```

**TypeScript Type:**
```typescript
export type TodayStatus = 'backlog' | 'todo' | 'in_progress' | 'done'
```

**Why these values?**
- Matches French column headers in UI
- Explicit naming (not generic "status1", "status2")
- Snake_case for consistency with database conventions

### Optimistic Updates Pattern

[Source: docs/prd.md#NFR2 + Story 1.11]

**What are optimistic updates?**
UI updates immediately when user takes action, before server confirms. This makes the app feel instant and responsive.

**Implementation with React Query:**
```typescript
onMutate: async (newTask) => {
  // 1. Cancel outgoing refetches (prevent overwriting optimistic update)
  await queryClient.cancelQueries({ queryKey: ['today', 'tasks'] })

  // 2. Snapshot previous value for rollback
  const previousTasks = queryClient.getQueryData(['today', 'tasks'])

  // 3. Optimistically update cache
  queryClient.setQueryData(['today', 'tasks'], (old) =>
    [optimisticTask, ...old]
  )

  // 4. Return context for rollback
  return { previousTasks }
},

onError: (err, newTask, context) => {
  // 5. Rollback on error (AC 12)
  queryClient.setQueryData(['today', 'tasks'], context.previousTasks)
},

onSuccess: () => {
  // 6. Invalidate and refetch to get real data (AC 11)
  queryClient.invalidateQueries({ queryKey: ['today', 'tasks'] })
}
```

**Benefits:**
- App feels instant (no waiting for server)
- Builds user trust (never feels sluggish)
- Critical for NFR2: "UI must be optimistic"

**Trade-offs:**
- More complex code (need rollback logic)
- User might see temporary ID briefly
- Need to handle conflicts (rare)

### Character Limits Rationale

[Source: docs/prd.md#Story 1.8 AC 1]

**Title: 200 characters**
- Enough for descriptive task names
- Prevents database overflow
- Keeps UI clean (no ultra-long titles)
- Twitter-like constraint encourages conciseness

**Notes: 2000 characters**
- Sufficient for detailed descriptions
- Roughly 300-400 words
- Prevents abuse (storing essays)
- Performance: Fast to load/render

**Frontend Error Handling:**
1. **Validation Errors (400):**
   - Show inline field errors
   - Highlight invalid fields in red
   - Prevent form submission until fixed

2. **Authorization Errors (401):**
   - Redirect to login
   - Clear auth tokens
   - Show message: "Session expired, please log in"

3. **Network Errors:**
   - Show toast: "Connection error. Check your internet."
   - Retry button
   - Queue request for later (Story 1.11)

4. **Server Errors (500):**
   - Show generic error: "Something went wrong. Try again."
   - Log error to Sentry
   - Provide retry button

5. **Optimistic Rollback (AC 12):**
   - Remove optimistic task from UI
   - Show error toast
   - Don't lose user's input (keep in form if modal still open)

import { QueryClient, QueryClientProvider } from '@tanstack/react-query'

const queryClient = new QueryClient({

- Loading/error states

### Modal UX Best Practices

**Accessibility:**
- Focus trap: Tab cycles within modal
- Escape closes modal
- Click overlay closes modal
- Focus returns to trigger button on close
- ARIA: `role="dialog"`, `aria-labelledby`, `aria-modal="true"`

**UX:**
- Auto-focus title input on open
- Enter (or Cmd+Enter) submits form
- Disable close during submission
- Clear form on successful submit
- Preserve form data on cancel (optional: ask "Discard changes?")

**Mobile:**
- Full-screen modal on small screens (<640px)
- Large touch targets (48px min)
- Bottom sheet style (slide up from bottom)
- Prevent background scroll when open
